# 资料库、歌手、专辑与展开播放器整改计划（2026-08-05）

## 背景与边界

本计划响应最新三张界面参考图，聚焦歌曲页、歌手详情、专辑详情的结构和交互缺口，并将
同一工作区中尚未提交的展开播放器修正一并验收。实现继续使用 Cadilume 自己的组件、图标
和数据边界；参考图只用于确认信息层级与操作密度，不复制第三方代码、资源或视觉资产。

- 保持唯一已确认归属 Cadilume 的 `pnpm tauri dev` 开发链，前端修改依赖 HMR，不另起实例。
- 歌单创建和写入继续只经过既有 `PlaylistPicker` 与 Rust/Tauri 命令，WebView 不直接访问 PMS。
- 所有新增纯图标按钮须具备 `aria-label`、`title`，并沿用现有居中 tooltip 锚点规则。
- 验收不新增截图；使用现有开发态的 DOM、computed style、控制台、可访问性和自动测试。

## 现状诊断

1. 歌曲页把总数放在标题下独占一行，`page-heading` 的固定高度又和分页工作区叠加，造成
   可见表格区域偏小、分页下方视觉留白过大；选中操作虽在 JSX 中存在，但与标题组混在一起，
   在窄高度和 sticky 标题下不够稳定、易被忽略。
2. `TrackTableGrid` 只提供歌手跳转，专辑单元格是普通文本；即使曲目已带 `parentRatingKey`，
   也没有经过统一的 `navigateToDetail` 路由守卫。
3. 歌手详情返回按钮仍含文字，歌曲 tab 的数量结构虽已存在，但未明确以同行基线/垂直居中
   约束；同类图标按钮需要统一确认 tooltip 和无障碍名称。
4. 专辑详情目前将专辑名作为主标题，并将“专辑 · 歌手名”作为副标题。这与目标信息层级相反，
   也缺少“添加到歌单”入口和统一的图标返回操作。
5. 展开播放器已在当前工作区改为左侧黑胶/封面切换、右侧主题与连接状态，并恢复右侧默认
   歌词列；它是本轮提交的一部分，不能因资料库整改回退。

## R1：歌曲页工作区与批量操作

### 修改

1. 将“共 X 首歌曲”嵌入“歌曲”标题同一行，作为紧凑计数，不再生成独占的段落副标题。
   加载和空状态继续以可读文本表达，避免把不确定数量伪装为计数。
2. 将已选数量和“播放 / 添加到播放队列”提升为标题右侧的独立操作区；它与标题同层且
   保持可见，不依赖表格滚动位置。两项仍沿用当前队列 API，操作成功后清空本页选择。
3. 为歌曲工作区设定可预测的高度分配：固定标题与分页高度，表格滚动容器吞掉剩余空间，
   分页始终在底部。在默认 `1280 × 820` 级别窗口内保持约 9 至 10 条标准歌曲行可见，
   不以新增全页滚动换取空间。
4. 保留现有首页/末页隐藏和上一页/下一页禁用逻辑；只压缩分页自身多余的垂直占位，不改变
   页码、排序、翻页重置表格滚动位置或页面缓存语义。

### 验收

- 标题、总数、选中摘要和两个操作按钮在同一 sticky 标题带内，无重叠或被裁剪。
- 未选中时标题带保持紧凑；勾选任意歌曲后两个操作均可见、可聚焦、可执行。
- 表格是歌曲页唯一垂直滚动容器；分页固定在其下，默认窗口显示约 9 至 10 条标准行。

## R2：曲目表的专辑导航

### 修改

1. 为 `TrackTableGrid` 增加专辑单元格组件：仅在曲目携带有效 `parentRatingKey` 时渲染可点击
   专辑名称；缺少标识时保留不可点击文本，不猜测或拼接路由。
2. 点击专辑单元格必须阻止歌曲行的播放冒泡，并通过 `LibraryContent` 现有的
   `navigateToDetail("album", ratingKey)` 进入详情。
3. 复用 `isCurrentLibraryDetailRoute()`：当前已处于该专辑详情时，点击同专辑名称不创建新历史
   条目、不重复读取、不触发白屏。该回调贯穿歌曲页、歌手歌曲、专辑曲目、歌单曲目和搜索曲目表。

### 验收

- 专辑名称可通过鼠标、键盘和无障碍名称触发导航，且不会同时播放歌曲。
- 同专辑详情中的专辑名称仍呈交互一致样式，但点击是安全 no-op；不同专辑正常进入新详情。
- 多歌手单元格现有“精确 ` / ` 拆分后本地匹配”的行为不受影响。

## R3：歌手详情与返回控件统一

### 修改

1. 将歌手详情左上“返回歌手列表”改为统一的 `ArrowLeft` 纯图标返回按钮，提供“返回歌手列表”
   的 `aria-label` / `title`，保持清晰焦点态。
2. 同样样式用于专辑详情返回，只由标签文本区分其可访问提示；视觉上为同一紧凑工具控件。
3. 明确歌手歌曲 tab 为 inline-flex 居中布局，“歌曲”和计数采用一致 line-height /
   alignment，数字不再上下漂移。
4. 审核此次触及的图标操作（返回、专辑跳转相关图标、歌手批量操作），补齐真实 tooltip
   和无障碍名称，不增加无意义的可见文字。

### 验收

- 两个详情页的返回控件尺寸、对齐、hover、focus 样式一致；悬停显示对应中文 tooltip。
- “歌曲  X”视觉垂直居中，tab 切换的 ARIA 键盘语义维持原样。
- 歌手列表头像已加入的主题对比描边在深浅色下仍保留。

## R4：专辑详情信息层级与歌单操作

### 修改

1. 将专辑英雄区改成三层：上方显示歌手、中央显示专辑名称、下方单独显示年份；不再呈现
   “专辑 · 歌手名”的拼接格式。没有歌手或年份时只隐藏对应层，不以错误占位替代。
2. 保留“播放 / 随机播放”，并增加“添加到歌单”图标操作，选择当前专辑全部已加载曲目，
   复用 `runtime.openPlaylistPicker()` 及既有创建新歌单流程。
3. 专辑详情内曲目表也启用 R2 的专辑跳转回调，因此当前专辑点击受到相同路由守卫。

### 验收

- 英雄区顺序为歌手、专辑、年份；信息不重复、长文本截断方式与既有详情页一致。
- “添加到歌单”能打开已有的歌单选择器，包含现有歌单和新建歌单路径，且不绕过 Rust 边界。
- 详情返回、播放、随机播放和添加到歌单在深浅主题下均无布局跳动。

## R5：展开播放器收尾保护

### 修改与验收

- 保留当前未提交的标题栏布局：左侧为收回与黑胶/封面切换，右侧为主题与连接状态。
- 右侧默认歌词列持续存在，复用活动行跟随、逐行 seek、加载/无歌词/错误状态；展开播放器
  底部不重复出现歌词开关。
- 歌手列表圆形头像的常态主题对比描边继续保留，作为深色可辨识性修正。

## R6：验证、计划回填与提交

1. 添加或更新针对静态布局、路由守卫、计数位置、歌曲选择操作、专辑层级和歌单入口的
   最小回归测试。
2. 在唯一开发链上进行无截图 HMR 验收：检查 DOM 结构、可访问名称、computed style、分页区域
   高度和控制台；不因已知裸 Debug 可执行文件 AX 限制重启应用。
3. 完整执行 `pnpm check`、`pnpm test`、`pnpm build`、
   `cargo test --manifest-path src-tauri/Cargo.toml`、`pnpm tauri build --no-bundle` 与
   `git diff --check`；全部通过后立即本地提交，不推送。
4. 最终进行项目记忆检查。将“展开播放器右侧歌词内容”和“底部歌词按钮”是两个独立需求的
   用户纠正保留在项目学习记录；其余仅在产生新的可复用结论时记录。

## 本轮实施与验收记录（2026-08-05）

### R1 歌曲页工作区与批量操作

- 将歌曲总数改为标题同行的 `track-page-count`，不再渲染独占副标题。
- 保留已选操作在标题右侧；在 HMR 开发态通过歌曲选择框实际触发，确认出现“播放”和
  “添加到播放队列”两个可访问按钮。
- 表格滚动区固定为剩余高度、分页固定为 `44px` 底部带，默认 `1280 × 720` 开发视口的
  数据区为 `406px`、单行 `47px`；按同一约束推导到默认 `1280 × 820` 应稳定容纳约 10 条
  数据行（另含表头），满足 9 至 10 行目标。

### R2 曲目表专辑导航

- 新增 `TrackAlbumCell`，仅在存在 `parentRatingKey` 时生成有名称和 tooltip 的专辑按钮；
  点击会停止歌曲行的播放冒泡。
- 全部曲目表统一传入 `openTrackAlbum()`，该函数只使用已有 `navigateToDetail()`，因此复用
  `isCurrentLibraryDetailRoute()` 的同页短路。
- HMR 开发态中从歌曲表进入专辑详情后，再点击同一专辑名称，URL、详情数量和页面标题均
  保持不变，控制台没有异常。

### R3 歌手详情与返回控件

- 歌手、专辑详情均使用 `DetailBackButton` 的纯 `ArrowLeft` 图标，分别携带“返回歌手列表”与
  “返回专辑列表”的 `aria-label` / `title`。
- 歌手歌曲 tab 的文本与计数改为同一 flex 对齐规则。HMR 开发态测得二者几何中心均为
  `316.32px`，且歌手的高频图标操作均具备中文 tooltip。

### R4 专辑详情层级与歌单入口

- 专辑英雄区现在按“歌手、专辑、年份、操作”渲染，移除了“专辑 · 歌手名”的拼接形式。
- 增加“添加到歌单”图标操作，实际打开既有 `PlaylistPicker`；开发态确认它带入当前专辑的
  全部 3 首歌曲，并保留新建歌单入口和已有歌单列表。

### R5 展开播放器收尾

- 保留未提交的播放器修正：标题栏左侧是收回和黑胶/封面，右侧是主题和连接；默认右侧歌词列
  存在，底部控制区不再重复显示歌词按钮。
- HMR 开发态确认该结构和所有关键 `aria-label`；主题切换期间 `#root` 的 computed
  `clip-path` 始终为 `none`，过渡只存在于旧主题快照，结束后快照被清理。
