## 2. 最新决定优先级

以下决定覆盖此前冲突需求：

1. **macOS AirPlay 完整删除**：公开 API 无法稳定复刻 Apple Music 的系统级体验，不再继续优化 `Show More`、设备发现动画或系统选择器；Windows 普通音频输出设备选择保留。
2. **暂时取消应用业务快捷键**：删除搜索聚焦、空格播放等全局快捷键及界面快捷键提示。搜索只保留可见输入框、点击和正常表单提交。
3. **歌单不显示刷新按钮**：早先“歌单标题右侧加刷新”已被后续要求取消；同步资料统一使用顶部刷新资料按钮，歌单失败态可保留“重试”。
4. **展开播放器恢复歌词**：早先“弹窗播放器不显示右侧歌词”的结论已被后续要求覆盖；展开播放器内部必须有歌词，并使用当前真实播放进度。
5. **最小/默认窗口固定为 `1280×800`**；Chrome 阶段验收仍按 `1280×820` 执行。
6. **字母索引顺序为 `#`、A–Z**；主页名称为“推荐”；所有面向用户的“播放列表”统一改回“歌单”，“艺术家”统一显示为“歌手”。
7. **今天不实施代码**：本文新增后的所有实现均留到下一上下文。

- `src/App.tsx`：确认 macOS 底栏、展开播放器和设备面板均无 AirPlay 入口；Windows 的“播放设备”入口继续存在。

- 删除仅为“保留 AirPlay 路由”存在的 URL 消费或 Audio 保留分支；若 helper 仍有其他调用方才保留。
- `src/useOutputDevices.ts`：删除 `activateOutputControl` 中的 AirPlay 结果和回调，收口为 Windows 输出设备能力；平台检测可以保留，但 macOS 不提供应用内设备按钮。
- 同步删除或改写 `usePlayer.test.ts`、`useOutputDevices.test.ts` 中所有 AirPlay 用例。

验收：macOS 最小窗口内完全没有 AirPlay 图标、设备按钮、提示或状态；连续切歌、暂停、恢复和预缓冲不依赖无线状态；Windows 输出设备选择不回归。

- 保留输入框原生复制、粘贴、全选、光标操作和 Enter 提交表单。

- 参考实现以 Ant Design 官方 [`useThemeAnimation.ts`](https://github.com/ant-design/ant-design/blob/master/.dumi/hooks/useThemeAnimation.ts) 和 [`ThemeSwitch`](https://github.com/ant-design/ant-design/blob/master/.dumi/theme/common/ThemeSwitch/index.tsx) 为准：先用 `document.startViewTransition()` 捕获根节点新旧快照，在回调中同步提交主题状态（React 更新必要时使用 `flushSync`），等 `transition.ready` 后，再对 `::view-transition-new(root)` 或 `::view-transition-old(root)` 使用 Web Animations API 改变 `clip-path`；动画期间临时关闭普通组件 transition，避免所有颜色各自交叉闪动。
- Cadilume 的第一视觉方案不是 Ant Design 的中心圆，而是以右上角主题按钮中心 `(x, y)` 为锚点的“掀被子”式弧形斜向揭示：优先使用非对称 `ellipse()` 或等价的圆弧 mask，让新主题从右上向左下展开，边缘保持柔和弧线；不制作夸张 3D 翻页、布料纹理或阴影卷边。时长控制在约 `450–520ms`，使用无弹跳的 smooth/ease-out 曲线，整个应用只发生一次连续揭示。
- 若弧形方案在 WKWebView/WebView2 中观感不自然、覆盖边界难以稳定或 CSS 动画能力不足，则按用户确认的方案回退为从同一右上角按钮向外扩散的圆。圆形路径使用 Ant Design 的计算：`endRadius = hypot(max(x, innerWidth - x), max(y, innerHeight - y))`，从 `circle(0px at x y)` 动画到 `circle(endRadius at x y)`，必须完整覆盖左下角，不以固定半径猜测。
- 无论浅→深还是深→浅，默认都让“新主题”从右上角向外揭示，不能一个方向扩散、另一个方向反向收缩造成认知不一致。选择“跟随系统”时，如果当前解析主题需要改变，可把这次用户点击作为动画原点；之后由系统自动触发的明暗变化没有点击坐标，直接平稳切换，不播放大面积掀开动画。
- 能力分级必须明确：`document.startViewTransition` 可用且未启用 reduced motion 时尝试弧形揭示；同一 API 可用但弧形验收不通过时使用圆形扩散；API 不可用、动画抛错或 `prefers-reduced-motion: reduce` 时原子切换主题并取消位移/裁切，不能克隆整棵 DOM、截图页面或用 Canvas 伪造快照。内部浏览器当前访问 Ant Design 时未暴露 `document.startViewTransition`，因此只能验收降级路径；主动画能力必须再由真实 Tauri WebView确认。
- 切换过程中顶部按钮暂时禁用，阻止连续点击叠加 View Transition；动画结束或失败都必须释放禁用态和临时 CSS。固定播放器、展开播放器、全局遮罩、Toast、浮层和原生标题栏内容应作为同一页面快照同步切换，过程中不得出现白屏、旧主题残块或错误层级。

验收：关闭态开关在深色下无需猜测即可辨识和操作；浅 / 深与三种配色均满足可见性与可访问性；主题切换仅呈现颜色揭示，封面和图片没有抖动、闪动或重新排版；推荐、歌曲、设置三页的标题与专辑 / 歌手视觉统一，分割线清晰且不影响滚动或路由稳定性。

#### R10 — 展开播放器机械唱臂、统一浮层与音量收口（P0，R9 后、L1/L2 前）

1. 修复展开播放器黑胶模式的机械结构。轴座、摆臂、唱头必须进入同一个转盘坐标系：轴座是摆臂的真实旋转锚点，臂杆从轴座边缘连续连接至唱头，唱头再稳定落在唱片有效半径内。不得让轴座、摆臂或唱头以互不相关的绝对坐标漂浮；封面比例、窗口尺寸、黑胶 / 封面模式切换、浅 / 深与三种配色下均不应断开、跳位或穿出唱片。
2. 主窗体与展开播放器的“播放队列”按钮使用同一个实用控制槽位、尺寸、图标、焦点样式与语义，且只调用应用根部唯一的 `queuePanel` 状态与渲染逻辑。移除展开播放器自身的队列状态和独立 `ExpandedQueuePanel`；队列始终沿用主窗体的浮层、透明遮罩、入/出场、焦点栈和单一列表数据，浮层内不增加关闭按钮，只由同一队列按钮、既有遮罩或既有键盘关闭语义收起。
3. 歌词也收敛为根部唯一的歌词浮层状态与内容，不能让展开播放器再生成第二套歌词面板或滚动状态。歌词浮层沿用队列的空间与 presence 约束但**没有遮罩**、没有关闭按钮、不能由 Escape、外部点击或其他入口关闭；主窗体固定底栏的歌词按钮是其唯一可见性开关。展开播放器只观察这套状态，不得与主窗体产生冲突或双重歌词。
4. 将主窗体和展开播放器目前两套音量计算、百分比输出、range 方向与 popover 几何收敛为有两个真实调用方的共享控制单元。百分比、填充轨道、静音图标和 `aria-valuetext` 必须来自同一个 `effectiveVolume`；静音不得丢失原独立音量，滑块从零上调应恢复声音。检查弹层锚点、纵向 range、滑块 thumb、数值基线与边界，确保在 0%、1%、50%、100%、静音、hover、键盘 focus、浅 / 深和三种配色中都可见、无裁切、无倒向或错位。
5. 本阶段只在内部浏览器的受控 fixture 完成 UI 与 DOM / computed-style 验收：测量轴座至臂杆首端的连接、唱头相对唱片半径、正常 / 展开态队列互斥与单例、歌词无 scrim 且仅底栏按钮可切换、以及全部音量状态矩阵。R8–R12 全部完成后，再复用唯一一条真实 Cadilume Tauri 开发链做统一验收；保持开发链不重启不等于提前完成原生验收，不截图、不启动第二条链。

验收：黑胶摆臂与轴座视觉连续且几何稳定；任一播放器入口打开的是同一张队列浮层，队列没有独立关闭按钮或双份状态；歌词无蒙层、无关闭按钮且只有底栏歌词按钮改变可见性；音量在正常和展开播放器中显示一致、读数正确、可操作且不溢出。

#### R11 — 原生状态图标与统一最小化（P0，R10 后、L1/L2 前）

1. 删除设置中“关闭主窗口时”的两个单选项、`CloseBehavior` 前端类型 / 状态、`set_close_behavior` IPC 和所有“关闭即退出”或“隐藏到托盘”的过期文案。主窗口收到关闭请求时始终阻止销毁并调用原生最小化；最小化不得暂停播放、丢失队列、清理登录态或重新请求钥匙串。状态图标的开关不得改变这一行为。
2. 在设置中新增一个紧凑开关，macOS 文案为“显示菜单栏图标”，Windows 文案为“显示任务栏图标”；这里的 Windows 图标明确指现有 Tauri 状态 / 通知区域图标，不把普通窗口任务栏按钮误作开关。文案与可用性由原生平台能力返回，不能在 macOS 显示 Windows 文案、反之亦然；不支持的平台不显示伪设置。
3. 用独立的持久化 `statusIconEnabled` 偏好替代旧关闭偏好：已有安装升级时静默删除 `closeBehavior`，默认保留现有体验（状态图标开启），并保留设备名称、品牌预设、client identifier 与登录凭据。bootstrap 返回实际开关值和当前平台标签；设置切换后立即更新原生图标，不要求重启、不重新登录、不产生第二个图标实例。
4. 状态图标开启时保留“显示 Cadilume / 播放或暂停 / 退出 Cadilume”的原生菜单及 macOS template 图标规则；关闭时完整移除该系统状态项和菜单。无图标时，最小化窗口仍必须可从普通 Dock / 任务栏恢复，不能让继续播放的应用变成没有可见回入口的后台进程；显式退出仍走唯一受控的原生退出路径。
5. 补齐 Rust 配置迁移、原生图标显隐、关闭动作和前端设置的定向测试；内部浏览器只验证平台文案、持久化 UI 状态和无旧选择器。此项涉及真实原生状态栏，允许在不重启、不另起实例的前提下复用当前唯一 Tauri 开发链做 macOS 实测；Windows 只能在实际 Windows 原生环境验证后才宣称已支持，不能以浏览器或 macOS 结果替代。

验收：设置页只剩一个随系统切换文案的状态图标开关，旧关闭行为选择与 IPC / 配置残留均为零；关闭窗口始终最小化并保持播放；开关立即显示 / 移除对应系统图标且重启后保持；关闭状态图标后窗口仍可从 Dock / 任务栏恢复，不存在不可见常驻进程。

#### R12 — 资料库密度、时长列与多歌手保真（P0，R11 后、L1/L2 前）

1. 调整所有歌曲表格共用的 grid 列定义。时长表头必须为“时长 + 排序图标 + 必要内边距”保留不可压缩的最小宽度，右对齐的数据列也保持稳定；在资料库歌曲、专辑详情、歌手歌曲、歌单、搜索以及“已选择歌曲 / 未选择歌曲”两种列数下，均不得裁切、重叠或挤掉表头和排序图标。不得以缩小标题字号、换行或移除排序图标掩盖问题。
2. 为歌手列表单独建立紧凑圆形头像网格，不改变专辑卡片尺寸或专辑详情封面。歌手头像及其卡片最大可见尺寸必须严格小于同一内容宽度下的专辑封面，网格在 `1280×820` 的最小桌面布局中应比专辑列表展示更多歌手；标题和必要元信息仍清晰、可聚焦，缺图占位也保持圆形几何。不得只用全局缩小 `.artwork-large` 伤及专辑、推荐或详情页。

4. 统一歌曲相关表面使用同一份完整歌手显示数据：歌曲表、专辑 / 歌手详情、歌单、搜索、播放队列、底栏、展开播放器与 Media Session 至少要保留完整姓名顺序。可由 PMS 标识或本地歌手索引确定详情的成员才渲染为可点击链接；未在资料库中找到或不能安全定位的成员仍显示为不可点击文本，保留完整可访问名称 / tooltip，绝不能因不可点击而被过滤、折叠成空白或与其他成员混淆。
5. 新增数据级回归：结构化多歌手、仅部分可匹配、全部不可匹配、名称含斜杠、旧式单一 `grandparentTitle` 和重复 / 空值必须各自覆盖；UI fixture 至少验证“多位成员都在 DOM 与可见文本中、只有可解析成员可跳转”。内部浏览器分别检查浅 / 深下的时长列、选择态表格、歌手网格密度和多歌手链接 / 不可链接状态；R8–R12 全部结束后才用当前唯一 Tauri 开发链做整轮真实 UI 验收，必要的真实 PMS 曲目验证只读其元数据与显示结果，不截图、不启动第二条链。

验收：任何歌曲表的“时长”表头和排序图标完整可见；歌手列表一屏可见人数增加且头像小于专辑封面；每首多歌手歌曲完整显示 PMS 返回的所有成员，能定位的成员可点击，不能定位的成员仍清晰可见但不可点击，不存在因匹配失败丢失姓名的情况。
