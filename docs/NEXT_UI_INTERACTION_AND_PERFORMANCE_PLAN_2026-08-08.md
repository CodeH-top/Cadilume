# Cadilume UI 交互与性能整改计划（2026-08-08）

本文承接 `NEXT_HANDOFF_AND_OPEN_ISSUES_PLAN_2026-08-07.md`。本轮不更换或改写已经完成压力
验证的 Rust 播放内核；目标是修复播放器周边的渲染、交互和路由问题，并以开发态真实
操作确认它们不再干扰播放体验。

## 1. 基线与边界

- 播放继续使用静态集成的 `rodio + cpal + symphonia`，不增加 SDK、动态库、sidecar、
  FFmpeg、mpv、BASS 或任何需要用户安装的依赖。
- 本轮问题均已定位在 React/WebView 展示层、路由缓存或 CSS 几何，不以替换音频引擎
  掩盖 UI 主线程问题。
- 保留且只使用当前唯一的 `pnpm tauri dev` 开发链；前端修改依赖 HMR。
- 不主动截取窗口或桌面；视觉验收使用用户提供的图片、DOM、computed style、事件和
  性能数据。
- Windows 不在本轮范围；macOS 开发态为实际验收目标。

## 2. 根因审查

### 播放器

1. 底栏小封面在曲目变化时立即把 `source` 清空，随后才异步申请 loopback artwork
   ticket；新 `<img>` 解码期间还会替换已显示节点，因此会短暂露出占位图或背景。
2. 展开歌词已有纵向滚动能力，但没有隐藏 WebKit scrollbar；不能用 `overflow:hidden`
   处理，否则滚轮和触控板也会失效。
3. 黑胶轴座、弯臂和唱头由三个独立绝对定位元素拼接。弯臂边框与轴座没有共享真实
   起点，缩放和旋转后会产生明显断口。
4. 两套歌词视图只在活动索引变化时发起平滑滚动，没有记录用户滚轮/触控板操作；容器
   自身的 `scroll-behavior:smooth` 又会让 WebKit 继续执行已被用户输入打断的动画。开头
   几句的目标位置均钳制为 0，因此最容易表现为下一句仍未夺回滚动控制。

### 歌曲与歌单

1. 歌曲总数位于粘性页头，与分页状态分离；用户翻页时信息层级不一致。
2. 行号只有播放按钮自身 hover 才切换成播放图标，缺少整行预显；按钮 hover 的主题色
   反馈与“可操作”提示被混为同一层。
3. 删除歌曲按钮使用 `display:none`。Popconfirm 获得焦点后行 hover 结束，锚点失去布局
   框，下一帧定位读到零尺寸；同时 `focus()` 可能触发捕获阶段 scroll 监听并立即取消。
4. 空歌单只使用通用 `min-height:220px` 空态，没有占据详情页英雄区以下的剩余高度。
5. 删除歌单复用完整编辑弹窗骨架，标题栏、关闭按钮、正文和页脚使一次二元确认显得
   过重。

### 设置与通知

1. 设置路由继承通用 40px 底部 padding，末组自身还保留 margin；播放器已经位于独立
   grid row，不需要重复预留这一整段安全区。
2. 视觉风格复用会渲染选中勾号的 `ChoiceCard`，同时为勾号永久预留右侧 34px。
3. 配色切换错误复用深浅主题的全窗过渡：克隆整棵应用树、读取全部媒体几何并把图片
   栅格化。配色只改变 CSS 变量，这个流程造成不必要的同步主线程负载。
4. 通知仍保留堆叠、hover/focus 暂停、ResizeObserver 测宽和 FLIP 位移动画。复杂状态
   既会使多条通知宽度漂移，也违背“无论窗口是否可见都按时关闭”的要求。

### 搜索

1. 搜索草稿位于 `MusicShell` 根状态。每个按键都会重渲染播放器、路由宿主、资料库和
   多个 Provider，播放进行时更容易暴露 WebView 主线程卡顿。
2. 连续提交搜索使用 push history；虽有 KeepAlive 清理旧搜索页面，仍会保留重复搜索
   History entry。

## 3. 实施批次

### A. 播放器视觉稳定性

- 为底栏播放器封面启用双阶段切换：保留上一张已显示图片，新 ticket 加载并完成图片
  load 后才原位替换；无封面或最终失败时才落到占位图。
- 展开歌词继续 `overflow-y:auto`，同时设置 Firefox/WebKit scrollbar 为零宽且不可见。
- 主歌词与展开歌词共用活动行滚动 hook：只由滚轮、触摸、滚动条指针和滚动键标记手动
  浏览；下一条可见歌词直接写入 `scrollTop` 瞬时夺回，空白时间帧保留该标记，普通切句
  继续平滑居中，并在下一帧重测活动行几何。
- 用一个统一 SVG 坐标系重建轴座、轴承、臂管、唱头和唱针；臂管路径从轴承中心连续
  出发，所有零件随同一舞台缩放。

验收：连续切歌时底栏旧封面保持到新封面可用；歌词可滚轮/触控板滚动且滚动条宽度为
0，手动滚离后下一句重新定位活动行；轴座与臂管端点无几何间隙。

### B. 歌曲与歌单交互

- 删除歌曲页头总数，把“共 X 首歌曲”放入分页条左侧；分页按钮保持视觉居中。
- 行 hover/focus-within 时用播放图标替代序号，但按钮仍为普通前景；只有按钮自身
  hover/focus-visible 时显示主题色、浅色背景和焦点反馈。
- 删除按钮始终保留 28x28 布局框，仅用 opacity/visibility/pointer-events 控制显隐；
  Popconfirm 打开时锁定锚点可见，并使用 `focus({ preventScroll:true })`。
- 空歌单、加载和错误态占满英雄区以下剩余高度并垂直居中。
- 删除歌单改成紧凑 alert dialog：警告图标、标题、一句包含歌单名的确认文案和两个
  按钮；支持 Escape、遮罩取消和初始焦点。

验收：真实点击“移除”会调用删除链路且不会自行消失；空歌单中心误差在可视剩余区内
可接受；行级与按钮级 hover 呈现两个清晰层级。

### C. 设置与通知

- 为设置路由添加专用底部 padding，并移除末组多余 margin。
- `ChoiceCard` 增加可关闭 check 的能力，视觉风格组不渲染勾号并回收右侧留白。
- 配色改为同步更新 CSS/React 状态并异步持久化，不创建全窗快照；深浅主题仍保留现有
  防图片闪烁过渡。
- 通知简化为固定统一宽度的纵向平铺列表：最多 5 条，第 6 条直接淘汰最老；每条从
  创建起独立计时 5 秒，不因 hover、focus、页面或窗口不可见而暂停；保留轻量进入和
  退出 presence，info 图标使用当前主题色。

验收：连续加入 6 条后 DOM 中最多 5 条且最老消息不存在；窗口/页面隐藏超过 5 秒再
恢复时没有过期消息；不同文案长度不改变队列外框宽度；配色点击不产生 transition
snapshot。

### D. 搜索路由与输入性能

- 把搜索 draft 移到独立、局部的搜索框组件，输入时只更新该组件，不再进入
  `MusicShellRuntime`，也不触发 KeepAlive 页面树重渲染。
- 当前已在 search route 时提交新关键词使用 replace；从非搜索页面首次搜索仍 push，
  以保留合理的返回路径。
- 路由 query 变化时局部同步输入框；继续销毁上一个 search cache，确保同时只保留一个
  搜索页面实例。

验收：长文本连续输入期间播放器进度仍推进；逐键操作不产生资料库请求；连续多次提交
搜索后只有一个搜索 KeepAlive 节点，后退不会逐个穿过旧关键词。

### E. KeepAlive 开发态兼容

`keepalive-for-react@5` 的官方约束明确禁止在开发态包裹 `React.StrictMode`。StrictMode
的额外挂载/卸载探针会让 portal 缓存节点无法可靠保留页面实例。入口改为单次挂载 `<App />`，
生产行为不变；页面切换时由 KeepAlive 将非活动节点移出文档树，但仍保留 React/DOM 实例和
滚动容器。

实际开发态回归确认：歌曲表格滚动 `360px` 后进入设置再使用 Back，滚动精确恢复；设置页滚到
底部 `136px` 后经过歌曲页再回退，仍恢复到 `136px`；Forward 可重新激活对应 History entry。

## 4. 自动化与开发态验证矩阵

| 范围 | 自动化 | 开发态实际检查 |
| --- | --- | --- |
| 封面 | 覆盖稳定图片切换状态 | 连续切歌检查旧图到新图的原位交接 |
| 歌词/唱臂 | 居中边界、手动夺回、空白帧与展开播放器结构测试 | wheel 后切句回位、scrollbar 为 0、SVG 端点连通 |
| 歌曲/歌单 | 分页、hover CSS 契约与 Popconfirm 点击 | 行 hover、按钮 hover、真实确认移除、空态几何 |
| 通知 | 5 秒、上限 5、淘汰最老、无暂停测试 | 加入 6 条、隐藏后恢复、逐条关闭与宽度测量 |
| 搜索 | 路由 replace/缓存契约 | 播放中输入、连续提交、History/KeepAlive 数量与响应耗时 |
| 设置 | 结构和样式检查 | 底部间距、无勾号、快速切换三种配色 |

实现完成后依次执行 `pnpm check`、`pnpm test`、`pnpm build`。Rust 源码本轮不改，但最终
仍进行一次实际 Tauri 开发态回归；若打包门禁需要，再执行对应 Tauri build。全部通过后
更新结果文档和项目记忆并在 `dev` 分支创建本地提交，不 push。

## 5. 完成结果

### 实现与开发态回归

- A-E 五个批次均已完成。`keepalive-for-react@5` 的本地 README 明确说明开发态不能与
  `React.StrictMode` 同用；入口改为单次挂载后，歌曲页 `360px`、设置页 `136px` 的滚动
  位置可经 Back/Forward 精确恢复。
- 通知 fixture 一次加入 6 条后仅保留最新 5 条，5 张通知均固定为 `360px` 宽，最老一条
  已移除；`5500ms` 后 DOM 中剩余 0 条。长 info 通知仍为 `360px`，图标颜色与当前
  `--accent` 一致。另有单元测试模拟后台计时器被节流、系统时间越过 deadline 后窗口重新
  聚焦，通知会立即进入退出态。
- 展开歌词实测视口高 `529px`、内容高 `5061px`，Firefox scrollbar 为 `none`、WebKit
  scrollbar 为 `0px`；容器中心滚轮输入后 `scrollTop` 从 `0` 变为 `332`。唱臂为单一
  `240x220` SVG，臂管路径从轴座中心 `M205 30` 连续出发，轴座和唱头均在同一坐标系。
- 针对开头歌词补充真实滚轮回归：主歌词首句从 `scrollTop=2200` 滚离后，切到第二句立即
  回到 `0`；展开播放器从 `2600` 切到第二句同样回到 `0`。两处均因顶部空间不足而正确
  钳制，正常中段仍平滑居中；计算样式为 `scroll-behavior:auto`，控制台无警告或错误。
- 歌曲总数只出现在分页条；整行 hover 显示播放图标但按钮背景仍透明，按钮自身 hover
  才出现主题色、浅色背景和描边。歌单移除 Popconfirm 可真实确认，行数从 6 递减至 0，
  计数同步；空态中心与英雄区以下剩余区域中心误差为 `0px`。删除歌单确认框实测
  `380x150.5px`，只保留一句确认文案和取消/删除两个按钮。
- 设置页滚到底后底部间距约 `7.97px`，三项视觉风格均无勾号。快速切换雨林绿、澄海蓝
  后最终状态为 `azure`，过渡快照数量始终为 0。搜索先提交 `Window` 再提交 `Light` 后，
  Back 直接回到提交搜索前的设置页，Forward 只恢复 `Light`；播放中连续输入 172 个字符
  约耗时 `14ms`，期间播放进度从 0 推进到 1 秒。
- 用包含完整封面元数据的新队列连续切换 6 首，底栏每次采样均保持 1 张已解码主图，
  没有占位帧。旧图只在新图请求/解码期间保留；新 ticket 最终失败时会退出旧图，避免
  长期显示上一首封面。浏览器恢复态不会持久化演示用 `data:` 封面，这是凭证/URL 安全
  边界；真实 PMS 队列持久化的是服务器相对 `thumb`，两条路径没有混用。

### macOS 系统媒体验收

- 在唯一 Tauri 开发链和真实 PMS 播放中，macOS 控制中心已显示完整曲名、歌手、专辑和
  封面，上一首、暂停/播放、下一首控制均可见。
- 控制中心暂停/恢复可同步 Cadilume；干净重启后单击一次“下一首”只产生一次系统命令和
  一次加载。此前重复行为来自旧 bundle 进程与旧监听残留，不是当前 Rust 队列重复消费。
- Rust 继续使用静态集成的 `rodio + cpal + symphonia`；本轮没有增加 SDK、sidecar、外部
  动态库或用户需安装的运行依赖，也没有重新打开 Windows 范围。
