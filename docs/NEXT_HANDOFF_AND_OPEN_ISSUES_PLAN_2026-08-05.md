## H1：《天地一斗》播放失败专项诊断

### 已知事实

- 真实曲目：周杰伦《天地一斗》。
- 最终错误：`MediaError code 4（格式或来源不受支持）`，WKWebView 没有提供 message。
- 已尝试：自动源、320 kbps、256 kbps、192 kbps，全部失败。
- 用户已决定本轮只预留，禁止在没有证据时直接调整转码参数、MIME 或加入特殊曲目规则。

### 诊断步骤

1. 在不输出服务器 URI、媒体路径、token、票据或曲目私有标识的前提下，为本机流代理增加
   脱敏的逐次尝试诊断：请求质量、实际质量、连接类型、端点类型、HTTP 状态、Content-Type、
   Content-Range/Length 是否存在，以及失败阶段。
2. 读取该曲目的真实 `Media.container`、`Media.audioCodec` 和 Part 响应类型，区分：
   - 原始文件本身不受 WKWebView 支持；
   - PMS universal transcode 返回非音频/错误响应；
   - 代理接受了状态成功但 Content-Type 不可播放的响应；
   - Range、HEAD/GET 或 `nosniff` 组合导致 WebKit 拒绝来源；
   - 播放器切源时序误把旧 source 错误归给当前 source。
3. 只在证据明确后修改对应层；重点核对官方文档使用的
   `/music/:/transcode/universal/start.mp3`、当前端点优先级和成功响应类型验证。
4. 回归原始可播放格式、需要转码的格式、自动/原始/三档码率、seek、暂停恢复和首首歌播放。

验收门槛：《天地一斗》实际有声音且时间轴连续推进；诊断信息能说明最终失败层，但不泄露任何
PMS 地址、路径或凭据；其他原本可播放歌曲不回归。

### 实施记录（2026-08-06）

- `src-tauri/src/stream_proxy.rs`：
  - 增加 `is_supported_audio_content_type()`，流代理只转发 `audio/*` 的 2xx/416 上游响应；
    不再把 PMS 返回的“状态成功但 Content-Type 不可播放”（典型为 `text/html` 转码错误页）
    原样交给 WKWebView，这是 `MediaError code 4` 的直接来源。
  - 转码端点保留 Plex Web 实际使用的 `/music/:/transcode/universal/start`
    （`protocol=http` 不带扩展名）优先，`start.mp3` 作为兼容回退；补充 `fastSeek=1`、
    `container=mp3`、`audioCodec=mp3`、`audioChannels=2`。
  - 修正 `X-Plex-Client-Profile-Extra` 为 Plex Web 的 musicProfile 语法，去掉
    `replace=true`（该参数只用于视频 `add-limitation`）。
  - 失败时返回脱敏诊断：已尝试端点数量、最后一次的请求质量/连接类型/端点类型/HTTP 状态/
    Content-Type；不包含 PMS 地址、路径、token、票据或曲目标识。
- 自动验证：`cargo test` 47 项通过；`pnpm tauri build --no-bundle` 通过。
- 待真实 PMS 回归：原始可播放格式、需要转码格式、自动/原始/三档码率、seek、暂停恢复、
  首首歌播放，《天地一斗》实际有声音。
