## 1. 展开播放器与播放队列

### 问题

- 展开播放器第一次打开时，左上角“收回”按钮会被初始焦点样式包上一圈过大的主题色边框。
- 播放队列标题缺少总歌曲数。
- 用户要求展开播放器不再显示歌词入口；歌词仍保持在主播放器和根部歌词面板中。
- 所有图标按钮的 tooltip 要以按钮水平中心为锚点，不因右侧布局而偏移。

### 实施

1. 将展开层初始焦点改为不触发可见 focus ring 的安全目标，或让程序化初始聚焦只使用 `:focus-visible` 的键盘可见规则；关闭按钮仍可被 Tab 正常聚焦。
2. 播放队列标题统一为 `播放队列(X)`，`X` 取当前队列长度，空队列状态保持原有语义。
3. 从展开播放器的控制栏移除歌词按钮及相关布局空位，不改变主播放器歌词按钮、无歌词 tooltip 或根部歌词面板。
4. 将共用 tooltip 的水平定位统一为 `left: 50%` 加 `translateX(-50%)`，并为边缘按钮保留不溢出窗口的约束。

### 验收

- 第一次打开和再次打开展开播放器时，收回按钮外没有异常主题色大框；键盘 Tab 到按钮时仍有清晰但紧贴控件的焦点提示。
- 标题准确显示当前队列数量。
- 展开播放器不显示歌词按钮，主播放器歌词行为不回归。
- 鼠标 hover 和键盘 focus 触发的 tooltip 均与所属按钮中心对齐。

## 2. 歌手页头部、动作与歌曲计数

### 问题

- 歌手名下重复显示“歌手”。
- 操作区空间足够，但“更多”菜单把高频操作藏起来；播放按钮不够突出。
- 歌曲总数被放在标题下方，应紧跟 `歌曲` 标题。

### 实施

1. 移除歌手名下的冗余类型标签，不影响无障碍标题层级。
2. 将“添加到队列”“播放下一个”“添加到歌单”从三点菜单提升为横向纯图标按钮，每个都有精确 tooltip 和 `aria-label`。
3. 保留扁长的主“播放”按钮，优先保证 1280px 最小窗口下不挤压头像、标题和资料文本。
4. 将歌曲 tab/区块的总数改为标题右侧的紧凑计数，例如 `歌曲 607`；数据加载前显示稳定占位，不造成标题跳动。

### 验收

- 页面没有多余“歌手”文字。
- 高级动作无需打开菜单即可触达，图标风格一致，tooltip 居中。
- `歌曲` 与总数处于同一行且保持可扫描间距。

## 3. 添加到歌单弹窗

### 问题

- 当前歌单条目是横向信息卡，包含无必要描述；选择窗不能在同一流程里新建歌单。

### 实施

1. 将歌单选择项变成纵向、紧凑、可滚动的列表，只显示封面、名称和必要的歌曲数量/只读状态。
2. 删除普通歌单描述的展示，保留受限写入状态的无障碍解释。
3. 在选择窗中直接提供“新建歌单”入口；创建成功后将新歌单加入本列表并可立即把当前选择的歌曲写入其中。
4. 保持 PMS 写入仍经现有 Rust/Tauri 命令，浏览器演示模式仅沿用既有模拟边界。

### 验收

- 列表为纵向浏览，不显示描述。
- 可在不关闭选择窗的情况下创建新歌单并添加当前歌曲/选中歌曲。
- 取消、失败、只读歌单和多首批量添加的反馈仍正确。

## 4. 主题切换的媒体稳定性

### 问题

- 现有快照几何冻结消除了常规位移，但实际主题切换仍可见图片闪烁或抖动，说明活动页面媒体仍在参与过渡或在快照/活页面切换的一帧重新合成。

### 实施

1. 采样活动媒体节点和快照节点的尺寸、位置、绘制属性，确认是布局变动还是同一节点的可见性/合成抖动。
2. 主题 reveal 生命周期中冻结活动媒体的 transform、filter、transition 和图像解码可见性；快照层只负责旧主题，不回写活页面布局。
3. 把媒体图片的主题相关背景与边框交给外层容器，避免 `img` 自身因主题变量、滤镜或透明度变化重新闪烁。
4. 保留正常 hover 与播放中的旋转效果，reduced-motion 路径不增加额外动画。

### 验收

- 深浅两个方向切换时，封面、头像、小黑胶和展开封面均无白闪、闪烁或可见位移。
- 页面滚动位置、图片裁切与交互状态保持不变。

## 5. 首次播放错误

### 问题

- 程序启动后的第一次播放会报错，需要区分音频元素初始化、首次 stream ticket、`loadedmetadata` 时序与重复 `error` 事件之间的关系，不能用吞掉错误掩盖真实失败。

### 实施

1. 审计首次调用 `loadAt()` 时双音频池、事件绑定和 stream ticket 的准备顺序，并用一次性请求身份防止旧的原生 `error` 事件误归属到刚分配的新 source。
2. 只有当前活动音频、当前 source 与当前加载请求同时匹配时才进入兼容串流回退；初始化/清空 source 的陈旧事件必须忽略。
3. 保留现有有限的质量回退与错误对话框，补充定向测试覆盖首次加载和陈旧 error 事件。
4. 真正的 PMS/网络/授权失败仍展示明确错误，不能被静默抹去。

### 验收

- 正常可用的第一首歌不出现误报错误。
- 真实 source、网络或授权失败仍可诊断并按既有路径回退/提示。

## 6. 歌曲页表格内滚动与分页固定

### 问题

- 歌曲页的滚动属于整页，翻页后需要从很长的页面重新定位到分页控件。

### 实施

1. 将歌曲页表格区域改为纵向 flex 布局：表头固定、数据区成为唯一滚动容器、分页栏固定在表格底部。
2. 保留当前列宽、排序、焦点顺序、行选中和最小窗口可用性；不把整个详情路由改成不可滚动。
3. 分页后数据区回到顶部，分页栏原地不动；总页数/当前范围更新但高度稳定。

### 验收

- 只滚动表格数据区即可浏览歌曲，分页始终可见。
- 切换页后无需滚动整页才能继续翻页或查看表头。

## 7. 歌曲分页与选中项操作

### 问题

- 分页首尾按钮文案不符合产品定义，且不应以 disabled 方式占位。
- 选中歌曲后没有可执行动作。

### 实施

1. 将首尾页按钮命名为“首页”“末页”；当前在首页时隐藏“首页”，当前在末页时隐藏“末页”，上一页/下一页的 disabled 和跳页逻辑保持不变。
2. 在歌曲表格的选择状态提供“播放”和“添加到播放队列”操作，按表格当前顺序处理所选歌曲；没有选中时不占据工具栏空间。
3. 主“播放”将选中集合替换为播放上下文并从首个选中项开始；“添加到播放队列”只追加去重后的选中歌曲，沿用播放器队列语义与通知反馈。

### 验收

- 首页不显示“首页”，末页不显示“末页”；上一页/下一页原行为不变。
- 选择一首或多首歌曲后可播放或加入队列，清空选择后动作区收起。
- 多选顺序、去重、无可播放项与队列反馈正确。

## 8. 多歌手分隔符间距

### 问题

- 多歌手在逐个拆分、分别匹配本地歌手库并渲染为独立可点击项后，HTML 的连续空白可能被压缩，导致斜杠紧贴两侧歌手名。

### 实施

1. 继续只以精确的 `" / "` 作为可拆分输入条件，保持原始歌手文本和本地匹配规则不变。
2. 在分段渲染中仅输出 `/`，将两侧的可见空白改为分隔符元素的固定 `margin-inline`；可点击与不可点击成员使用同一布局。

### 验收

- `S.H.E / 飞轮海` 等拆分显示时，斜杠与两边的歌手名始终保持等宽留白。
- `AC/DC`、`A/B`、`A /B`、`A/ B` 等未拆分文本不受影响。

## 9. 队列交互、长列表与歌词互斥

### 问题

- 队列歌曲可点击播放，却没有明确的 hover / focus 播放反馈；长队列开关时会额外占用布局与绘制资源。
- 主窗体歌词正文比播放器队列歌曲标题明显更大。
- 已打开歌词时直接打开播放队列，会让两个浮层短时间并行，造成切换不连贯。

### 实施

1. 队列项封面增加仅在 hover / keyboard focus 时出现的播放提示层，行背景和标题同时给出轻量反馈。
2. 队列滚动区增加独立滚动控制；队列项用 `content-visibility: auto`、containment 与稳定固有高度跳过离屏绘制，队列组件继续保持 memo 化，避免进度更新重绘整列。
3. 普通歌词主文本统一为 `14px / 650`，翻译/次级文本统一为 `12px`，与队列的信息层级一致。
4. 点击队列时，若歌词正在打开则先令歌词进入关闭态，再在同一面板动效结束后挂载队列；reduced-motion 下仍保持先后顺序，只缩短等待时间。

### 验收

- 队列项拥有播放提示层，长队列离屏项的 computed `content-visibility` 为 `auto`。
- 歌词正文的计算字号为 `14px`；队列标题正确包含当前数量。
- 演示态与真实开发态均可从歌词切换到队列，且根状态只有一个活动浮层。

## 10. 黑胶与唱臂视觉

### 实施

1. 小黑胶不使用可见外框；深色主题提升唱片纹路、内高光和反向色淡光晕，保持浅色主题不出现白边。
2. 展开播放器使用更清晰的同心轴座、缩短的金属摆臂和更轻的唱头/唱针比例，所有元素继续以同一唱臂旋转锚点定位。

### 验收

- 深色主题中小黑胶和纹路可辨，但没有显式边框。
- 轴座、摆臂、唱头不会在模式/尺寸切换中脱离同一坐标系；主观观感由用户在原生窗口复核。
